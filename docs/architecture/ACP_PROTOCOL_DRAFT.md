# ACP — Agents Context Protocol (Draft v0.1)

> **Status:** Draft | **Date:** 2026-04-15 | **Author:** AKIS Team

## 1. Overview

ACP (Agents Context Protocol) defines the standard message format for agent-to-agent communication in multi-agent verification pipelines. It ensures that context, constraints, and trust metadata flow correctly between pipeline stages regardless of the domain.

**Design principles:**
- Agents are stateless — all context travels in the message envelope
- Review agents MUST run in fresh context (session isolation)
- Trust metadata is append-only (no stage can remove previous trust signals)
- Human approval is an explicit, non-bypassable message type

## 2. Message Types

### 2.1 TaskRequest
Sent to a producing agent to initiate work.

```typescript
interface TaskRequest {
  type: 'task_request';
  id: string;           // unique message ID
  pipelineId: string;
  stage: string;
  domain: string;
  input: {
    specification: unknown;   // domain-specific spec
    constraints: Constraint[];
    context: string;          // human-readable context
    learnings?: string;       // injected past learnings
  };
  trust: TrustMetadata;
  replyTo?: string;     // message ID this is responding to
}
```

### 2.2 TaskResult
Returned by a producing agent after completing work.

```typescript
interface TaskResult {
  type: 'task_result';
  id: string;
  pipelineId: string;
  stage: string;
  output: {
    artifact: unknown;       // domain-specific output
    decisions: Decision[];   // what was decided and why
    confidence: number;      // 0-100
    openQuestions: string[];  // unresolved ambiguities
  };
  trust: TrustMetadata;
  inReplyTo: string;     // original TaskRequest.id
}
```

### 2.3 ReviewRequest
Sent to a reviewing agent (e.g., Critic) to evaluate work.

```typescript
interface ReviewRequest {
  type: 'review_request';
  id: string;
  pipelineId: string;
  stage: string;
  artifact: unknown;          // what to review
  specification: unknown;     // what it should conform to
  reviewType: string;         // 'spec' | 'code' | 'document' | 'report'
  trust: TrustMetadata;
  sessionIsolation: true;     // MUST always be true — reviewer has fresh context
}
```

### 2.4 ReviewResult
Returned by a reviewing agent after evaluation.

```typescript
interface ReviewResult {
  type: 'review_result';
  id: string;
  pipelineId: string;
  stage: string;
  verdict: {
    approved: boolean;
    score: number;            // 0-100
    findings: Finding[];
    summary: string;
  };
  trust: TrustMetadata;
  inReplyTo: string;
}
```

### 2.5 HumanApproval
Explicit human decision — cannot be generated by any agent.

```typescript
interface HumanApproval {
  type: 'human_approval';
  id: string;
  pipelineId: string;
  decision: 'approve' | 'reject' | 'modify';
  feedback?: string;
  userId: string;
  timestamp: Date;
  /** Auto-approval flag — set only when adaptive autonomy threshold is met */
  autoApproved?: boolean;
  autoApproveScore?: number;
}
```

## 3. Envelope Format

Every ACP message is wrapped in a standard envelope:

```typescript
interface ACPEnvelope {
  version: '0.1';
  message: TaskRequest | TaskResult | ReviewRequest | ReviewResult | HumanApproval;
  metadata: {
    timestamp: Date;
    source: string;        // agent or system that created this
    domain: string;
    pipelineId: string;
  };
  trust: TrustMetadata;
}
```

## 4. Trust Metadata

Trust metadata is append-only and travels with every message.

```typescript
interface TrustMetadata {
  /** Confidence score from the producing/reviewing agent */
  confidence: number;
  /** Hash of the verification chain up to this point */
  verificationChainHash: string;
  /** Human approval status */
  humanApproval: 'pending' | 'approved' | 'rejected' | 'auto_approved';
  /** Deterministic validation result (if available) */
  validationScore?: number;
  /** Security gate result (if available) */
  securityGateResult?: 'passed' | 'blocked' | 'regression';
  /** Full audit trail of who touched this artifact */
  auditTrail: AuditEntry[];
}

interface AuditEntry {
  agent: string;
  action: string;
  timestamp: Date;
  result: 'success' | 'failure' | 'warning';
  details?: string;
}
```

## 5. Session Isolation Rules

**Critical safety requirement:**
- Review agents (Critic) MUST run in a fresh LLM session
- No shared context between producing and reviewing agents
- The ReviewRequest message is the ONLY input the reviewer receives
- This prevents confirmation bias and ensures adversarial independence

**Implementation:**
- Each ReviewRequest creates a new AI session (no conversation history)
- The system prompt for reviewers does NOT include the producer's reasoning
- Reviewer agents cannot access the producer's intermediate state

## 6. Constraint Types

```typescript
interface Constraint {
  type: 'hard' | 'soft';
  category: string;     // 'security' | 'performance' | 'compliance' | 'style'
  description: string;
  source: string;       // who imposed this constraint
  verifiable: boolean;  // can be checked deterministically
}
```

## 7. Decision Record

```typescript
interface Decision {
  what: string;         // what was decided
  why: string[];        // reasoning factors
  alternatives: string[];  // what else was considered
  tradeoffs: string[];  // acknowledged tradeoffs
  confidence: number;   // how sure (0-100)
}
```

## 8. Future Extensions (Horizon 3)

- **Streaming:** Long-running agents emit progress messages
- **Branching:** Multiple review paths in parallel (consensus voting)
- **Cross-pipeline:** Agent in Pipeline A requests artifact from Pipeline B
- **Federation:** ACP messages between different AKIS instances
- **Encryption:** End-to-end encryption for sensitive domain data
