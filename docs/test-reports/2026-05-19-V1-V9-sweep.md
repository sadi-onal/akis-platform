## Per-fix coverage

### V1 — Resizer Pointer Events (`useSplitResize`)

Existing tests: 3 happy-path. **6 new edge cases**:

- _ignores move events whose pointerId does not match the captured pointer_ — stray touch in a touch+mouse interleave must not steal the drag.
- _ignores end events whose pointerId does not match — drag remains active_ — the body-cursor lock and `releasePointerCapture` are gated on the captured id; a stray pointerup must not end the real drag.
- _handleDragMove with no drag in progress is a no-op_ — defensive guard against unmount-during-drag or replay.
- _handleDragMove is a no-op when splitContainerRef.current is null_ — defensive: ref unattached → no crash, no setPreviewWidth call.
- _handleDragEnd swallows a releasePointerCapture throw (lost-pointer recovery)_ — browsers throw `InvalidStateError` when focus is lost mid-drag; the hook must still restore body styles.
- _unmount when no drag is active does NOT touch body styles_ — the cleanup is conditional on `isDraggingRef.current`; pins that the hook doesn't stomp on the surrounding app's cursor.

## Recommendations (out of scope for this PR)

- **V1 — pointermove threshold:** the hook accepts micro-movements (<1 px) as drag updates. Adding a small "drag intent" threshold (e.g. 2 px from start) would prevent accidental width nudges from a misclick. Test would be straightforward (assert `setPreviewWidth` is NOT called for 1-px moves below threshold).
- **V3 — IME composition guard:** browsers fire `Enter` keyDown _during_ active IME composition with `isComposing: true`. The current handler does not check this and would submit a half-typed Japanese/Chinese sentence. Add `if (e.nativeEvent.isComposing) return;` to both LoginEmail and LoginPassword Enter handlers; existing tests stay green and add a positive test for `keyDown({ isComposing: true })` ⇒ no submit.
- **V4 — apply-toast dismiss:** the toast has no explicit close button — users must wait the 4-second timer. Adding a "kapat" affordance with `keyboard: Escape` shortcut would be a small UX win.
- **V5 — failed-status surface:** the cinema column shows "active" for a failed stage when uiState matches (e.g. `trace_running` while a `status='failed'` activity arrives). A `state='failed'` view would tell the user which column actually crashed.
- **V6 — XSS hardening:** the disclosures render user/AI-provided strings via React text. A `dangerouslySetInnerHTML` regression here would silently open an XSS hole. Consider adding a runtime guard `typeof content === 'string'` at component boundary or — better — typing the spec fields as a branded `SafeString` so the type system catches future "render as markdown" attempts.
- **V8 — token budget:** the user-prompt builder serializes the entire artifact with `JSON.stringify(..., null, 2)`. For very large specs (many AC + technical constraints) this can push the prompt into the model's context limit. Consider compacting / structured sub-prompts.
- **V9 — branch is unmerged on main:** V8 + V9 are still on open PR branches (`pr-v8-critic-stack-false-positive`, `pr-v9-preview-session-leak`). After they merge, this branch's V8/V9 sections should be expanded to cover the new code paths (V9 sessionId transitions; V8 prompt clauses).
- **Backend CI gap (`src/__tests__/`):** `pnpm test:unit` only runs `test/unit/*.test.ts`. A whole tree of co-located tests under `backend/src/**/__tests__/*.test.ts` (e.g. CriticAgent, prompts, RegressionService, FixLoopService, ExplainabilityService) is currently NOT exercised in CI. Either extend the test:unit glob to include `src/**/__tests__/*.test.ts` or migrate those files into `test/unit/`. Until then, the V8 additions in this PR — and the equivalent V8 tests on the `pr-v8` branch — are only verifiable via direct invocation.
